# 01 · 目的与边界

## 用户需求（原文摘要，m00256）

- 会话页面「视图选项 → 分组方式」目前只有 **按工作区 / 按工作区树 / 单列表**，希望追加 **自定义分组**。
- **只改显示逻辑，不改变本地排列**。
- 用户可以自己创建分组，然后**拖动**把会话拖进去，自己管理同类别的会话。
- 拖进分组后，分组识别会话的 **session id**（等同右键「复制会话 ID」拿到的 UUID），据其显示；**其它地方不再显示** —— 即「显示的唯一性」。
- 还要能**很简单地拖出**分组。
- 设计细节用户未完全考虑，要求**务必先对话对齐设计意图**。

## 目标（v1）

1. 「分组方式」新增第四项 **自定义分组**，与既有三项并列、互斥、可随时切回。
2. 分组模型：用户可创建/重命名/删除/排序分组；分组是**跨工作区**的容器（成员按 session id 记录）。
3. 拖拽：会话可从「未分组」或其它分组拖入目标分组；可拖回「未分组」；分组头可拖拽调序。
4. 显示唯一性：自定义分组模式下，一个会话**最多出现在一个分组**；已归组会话不再出现在任何工作区分组里。
5. 纯前端：不新增 host 路由、不改 `workspaces`/会话数据、不改 profile 的 `cordis.patch.yml` 以外的服务端状态。
6. 可回滚：一个 patch 行 + 一次 `dsh plugin` 操作即可退回原生三选项。

## 非目标（v1 明确不做）

- 会话真实的 `workspaceId` 迁移、跨工作区物理搬移、工作区合并/拆分。
- 分组嵌套（分组里再建分组）—— 数据结构预留 `parentId`，UI 不做。
- 多端/多浏览器同步（v1 用 localStorage，见 06 的待裁决问题 Q6）。
- 标签式「一个会话属于多个分组」（与「显示唯一性」冲突，明确排除）。
- 修改 core 的三选项行为、或删掉「按工作区」等原生模式。
- 与 DSH 上游 merge 的长期分叉治理（只做「可机械重打补丁」的 vendor 管线）。

## 验收标准（v1）

- [ ] 切换四种分组方式，侧栏不闪退、不重复渲染、状态在刷新后保留。
- [ ] 新建分组 → 拖 3 个会话进去 → 刷新页面，分组与成员仍在；被拖走的会话不再出现在原工作区分组。
- [ ] 把成员拖回「未分组」→ 它回到原来的工作区显示（因为底层从未改动）。
- [ ] 删除分组 → 成员全部回到未分组，不丢会话。
- [ ] 搜索、归档筛选、手动排序/最近更新、置顶、折叠状态在自定义模式下行为自洽（见 06）。
- [ ] 关闭/卸载插件后，UI 完全回到原生三选项（无残留 DOM、无报错）。
- [ ] 无新增 console error；无新增 host 路由。
